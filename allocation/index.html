The buy will not cover the estate

A single unit on a fixture is a gap rather than a facing, so a run has a floor — which is what makes this a choice of doors instead of a division of units

Spread evenly, every door gets 1.8 units and none of them can sell itCortex
Dividing 590 launch units across 325 doors gives each one 1.8 units across the 4 sizes this style is made in — well under the 8 units a presentable run needs, so it is a broken run everywhere and nowhere to buy the style from. That allocation always produces a number for every door, which is exactly why it gets used, and it strands the entire buy. Concentrating the same units into 70 doors is not a smaller ambition, it is the only version that sells at full price.

The doors on either side of this line score identically — same grade, same cluster, same selling space — so the cut between them is a tie-break rather than a judgement. A reserve only earns its keep on the units a blind launch would have misplaced — 111 here, taken from this style's own measured imbalance rather than assumed. Beyond that, extra reserve buys nothing and simply sits in the distribution centre, while the cost keeps climbing: deeper hold-back starts dropping the doors that would have sold the style fastest, which is why the net figure turns over and eventually goes negative. On this buy the curve choice barely matters, and that is worth knowingCortex
The buy only reaches one size profile — full-space, above-average catchment (70 doors) — and it carries the full run this style is made in. So the two methods allocate the same shape, and claiming a saving here would be inventing one. The doors whose profile departs from the chain curve are the small ones, and a buy thin enough to cut the tail never reaches them: the chain curve's error is a depth problem on a deep buy, which is why it shows up as stranded stock later rather than as a bad launch.

“How should we allocate the Kit Wool Blazer buy at launch?”
To 70 of 325 doors, holding back 20%. The buy is 737 units and giving every door a run it can sell from would need 2,600, so spreading it puts every door below a presentable depth. Serving 70 doors in demand order reaches 590 units at 2.1 per size, and cuts 255 doors — 255 of them because the units ran out, not because they cannot trade the style. Holding back 20% keeps 147 units to re-aim once there is real sell-through to read, worth £1,829 net of the launch sales it gives up.

Semantic view: CALLA.MERCH.SV_ALLOCATION
-- Launch allocation: rank doors on what they can sell, serve each in
-- full or not at all, and stop when the launch quantity is exhausted.
WITH buy AS (
  SELECT
    po.STYLE_CODE,
    SUM(po.UNITS) AS buy_units,
    ROUND(SUM(po.UNITS) * (1 - 0.20)) AS launch_units
  FROM CALLA.MERCH.FCT_PURCHASE_ORDER po
  WHERE po.STYLE_CODE = 'OW-BLZ-012'
  GROUP BY po.STYLE_CODE
),
door_weight AS (
  SELECT
    l.LOCATION_ID,
    l.CLUSTER_ID,
    l.GRADE,
    -- No sell-through exists for a launch, so the forecast is the door's own
    -- attributes: grade sets the level and selling space scales it.
    CASE l.GRADE WHEN 'A' THEN 1.0 WHEN 'B' THEN 0.62 WHEN 'C' THEN 0.34 ELSE 0.18 END
      * (l.SPACE_SQM / 500) AS weight
  FROM CALLA.MERCH.DIM_LOCATION l
),
ranked AS (
  SELECT
    dw.*,
    dw.weight / SUM(dw.weight) OVER ()                       AS demand_share,
    ROW_NUMBER() OVER (ORDER BY dw.weight DESC, dw.LOCATION_ID) AS rank
  FROM door_weight dw
),
-- What it costs to serve a door properly: every ranged size at least at the
-- presentation minimum, and the rest to demand.
door_cost AS (
  SELECT
    r.*,
    b.launch_units,
    COUNT(sp.SIZE_CODE)                                      AS sizes_ranged,
    GREATEST(
      COUNT(sp.SIZE_CODE) * 2,
      ROUND(b.launch_units * r.demand_share)
    )                                                        AS required_units
  FROM ranked r
  CROSS JOIN buy b
  JOIN CALLA.MERCH.BRG_LOCATION_SIZE_PROFILE blsp
    ON blsp.LOCATION_ID = r.LOCATION_ID
   -- The estate is re-cut each season, so the bridge must be scoped to a cycle
   -- or a door picks up every profile it has ever belonged to.
   AND blsp.CYCLE      = 'SS26'
  JOIN CALLA.MERCH.DIM_SIZE_PROFILE sp
    ON sp.SIZE_PROFILE_ID = blsp.SIZE_PROFILE_ID
   AND sp.IS_RANGED
  JOIN CALLA.MERCH.BRG_STYLE_SIZE_RANGE ssr
    ON ssr.STYLE_CODE = 'OW-BLZ-012'
   AND ssr.SIZE_CODE  = sp.SIZE_CODE
  GROUP BY r.LOCATION_ID, r.CLUSTER_ID, r.GRADE, r.weight,
           r.demand_share, r.rank, b.launch_units
)
SELECT
  LOCATION_ID,
  CLUSTER_ID,
  GRADE,
  rank,
  ROUND(demand_share * 100, 3)                               AS demand_share_pct,
  sizes_ranged,
  required_units,
  SUM(required_units) OVER (ORDER BY rank)                   AS cumulative_units,
  -- A door is served in full or not at all: a part-served door has a broken run
  -- that cannot fit a walk-in, so those units would sit until marked down.
  IFF(SUM(required_units) OVER (ORDER BY rank) <= launch_units, required_units, 0)
                                                             AS allocated_units,
  IFF(SUM(required_units) OVER (ORDER BY rank) <= launch_units,
      'served', 'units-exhausted')                           AS outcome
FROM door_cost
ORDER BY rank;
