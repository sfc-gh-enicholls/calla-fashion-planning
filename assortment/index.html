Selector-driven readout of the live scenario shift.

“Where is the flare slot shift landing most heavily?”

The live scenario still matches the base assortment, so there is no cluster movement to explain yet.

Generated SQL
Semantic view: SV_ASSORTMENT
WITH assortment_shift AS (
  SELECT
    cluster_id,
    cluster_name,
    style_code,
    slot_pct_base,
    slot_pct_scenario,
    slot_pct_scenario - slot_pct_base AS flare_shift_pts
  FROM CALLA.MERCH.SV_ASSORTMENT
  WHERE cycle = 'SS26'
    AND style_code = 'DN-FLR-002'
)
SELECT
  cluster_name,
  slot_pct_base,
  slot_pct_scenario,
  flare_shift_pts
FROM assortment_shift
ORDER BY flare_shift_pts DESC;
