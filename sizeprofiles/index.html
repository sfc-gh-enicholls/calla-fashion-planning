A cluster curve is only worth the volume behind itCortex
France Regional sold 114 units of Ines Flare Jean across the run it carries, so its own shape is planned at 43% weight and the rest comes from the curve above it. London, on 324 units, is trusted at 68%. Without that weighting a door with a handful of sales per size would drive a curve as hard as one with hundreds — which is how a size process ends up reversing itself every season and losing the planners who have to defend it.
The aggregate is what hides itCortex
Rebuilt at chain level the curve moves by at most 2.7 points, so a planner reviewing the total would reasonably conclude it was fine. London alone wants 1.46 times the chain share of XS. The skews run in opposite directions and cancel, which is exactly why a single curve survives review.

Why the mixed option winsCortex
Handling cost and clearance risk both scale with the size of the buy, so a fixed ratio pack can never overtake eaches on total cost however large the order. Taking the core in packs and picking XS and XXL to the curve keeps the fit exact and still saves £101 against picking everything as eaches. The cost is two receipt streams to manage rather than one.

Semantic view: CALLA.MERCH.SV_SIZE_PROFILE
-- Size demand by profile against the single chain curve the buy was placed on
--
-- Grouped by size profile rather than by trading cluster: profile membership is
-- derived from store attributes and cuts across clusters, which is the finding
-- rather than an implementation detail.
WITH cell AS (
  SELECT
    b.SIZE_PROFILE_ID,
    st.SIZE_CODE,
    SUM(st.UNITS_SOLD)    AS observed_units,
    SUM(st.CLOSING_STOCK) AS stock_on_hand,
    COUNT(DISTINCT st.CLUSTER_ID) AS clusters_spanned
  FROM CALLA.MERCH.FCT_TRADING_WEEK st
  -- A bridge, not a column on DIM_LOCATION: the grouping re-cuts each season, so
  -- a door can change profile without rewriting history.
  JOIN CALLA.MERCH.BRG_LOCATION_SIZE_PROFILE b
    ON b.LOCATION_ID = st.LOCATION_ID
   AND b.CYCLE       = st.CYCLE
  WHERE st.STYLE_CODE = 'DN-FLR-002'
    AND st.ISO_WEEK   = 18
  GROUP BY 1, 2
),
shaped AS (
  SELECT
    cell.*,
    p.SIZE_PROFILE_NAME,
    p.IS_RANGED,
    cell.observed_units
      / NULLIF(SUM(cell.observed_units) OVER (PARTITION BY cell.SIZE_PROFILE_ID), 0)
      AS observed_share,
    p.DEMAND_SHARE                             AS true_share,
    p.DEMAND_SHARE / NULLIF(ch.CURVE_SHARE, 0) AS index_vs_chain
  FROM cell
  JOIN CALLA.MERCH.DIM_SIZE_PROFILE p
    ON p.SIZE_PROFILE_ID = cell.SIZE_PROFILE_ID
   AND p.SIZE_CODE       = cell.SIZE_CODE
  JOIN CALLA.MERCH.DIM_SIZE ch
    ON ch.SIZE_CODE = cell.SIZE_CODE
)
SELECT
  SIZE_PROFILE_NAME,
  SIZE_CODE,
  clusters_spanned,
  ROUND(observed_share * 100, 1) AS observed_share_pct,
  ROUND(true_share     * 100, 1) AS true_share_pct,
  ROUND(index_vs_chain, 2)       AS index_vs_chain,
  -- Out of scope is a strict zero, not a small share: a profile that does not
  -- range a size has no demand for it at any price.
  IS_RANGED,
  -- Rationing: nothing left on the shelf while the style still sold, so the
  -- observed share understates demand and cannot be used to fix the curve.
  IFF(stock_on_hand = 0 AND observed_units > 0, TRUE, FALSE) AS was_rationing
FROM shaped
ORDER BY ABS(index_vs_chain - 1) DESC;
